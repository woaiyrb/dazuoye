# 初中数学作业 AI 平台：MVP 实施基线

> 本文以《数学作业AI项目——开发前需求确认问题清单》为准。旧的 Mark 功能只作为可复用的交互和技术参考；与需求文档冲突的功能不进入第一版。

## 1. 第一版范围

- 角色：教师、学生、教研负责人。
- 题型：单选题、判断题。
- 判分：Java 后端根据标准答案确定对错和得分。
- AI：只负责错误总结、错误模式、可能原因、题目讲评、知识点总结、整体总结和练习建议。
- AI 输出：只生成草稿，必须由教师修改、确认后才能发布。
- AI 不可用：教师仍可手工填写、审核和发布讲评。
- 教学闭环：批改 → 统计 → AI 草稿 → 教师审核 → 发布 → 学生查看 → 订正。
- 可追溯：讲评草稿保留作业、标准答案、教师材料、统计数据等依据。

## 2. 当前实现

### 前端

- 目录：`apps/web-vue`
- 技术：Vue 3、HTML 模板、CSS、JavaScript。
- 已实现页面：
  - 中文登录页
  - 教师工作台
  - 作业概览与选择/判断题统计
  - 批改统计
  - AI 讲评审核与发布状态
  - 学生订正跟踪与教师确认
  - 班级学生、知识点、系统状态
  - 学生作业入口
  - 三列紧凑批量出题工作台：出题设置、教学材料、结果预览
  - 学生作答、Java 确定性判分、逐题结果
  - 学生查看已发布讲评、提交错题订正
  - 教师查看并确认学生订正
- 响应式：桌面侧边栏、平板/手机抽屉导航。
- 可访问性：跳转主内容链接、键盘焦点、44px 交互目标、减少动画支持。
- 数学公式：KaTeX 渲染，避免显示原始 `$...$` 标记。
- 编码：启动脚本、Python 和 PowerShell 输出统一为 UTF-8，防止终端中文乱码。

### Java 后端

- 目录：`apps/api-java`
- 技术：Java 17、Spring Boot、Maven。
- 数据库：现有 MySQL `mark` 库，Java 通过 JDBC 直接读写题目。
- 数据库健康检查：`GET /health/database`
- 已实现：
  - `/health`
  - `/java-api/ai/status`
  - `/java-api/reviews/{assignmentId}` 讲评草稿读取与保存
  - `POST /java-api/reviews/{assignmentId}/generate` 调用 DeepTutor 生成讲评草稿
  - `POST /java-api/generator/generate` 按题型和数量调用 DeepTutor `deep_question`
  - `POST /java-api/generator/assignments/{assignmentId}/import` 导入教师勾选的题目
  - `/java-api/student/assignments/{id}/questions` 学生安全题目视图
  - `/java-api/student/assignments/{id}/submit` Java 确定性判分
  - `/java-api/student/assignments/{id}/corrections` 学生订正
  - `PATCH /java-api/student/corrections/{id}/confirm` 教师确认订正
  - `/java-api/editor/assignments/{id}` 题目编辑器读取
  - `/java-api/editor/assignments/{id}/questions` 题目新增、保存和软删除
  - 讲评状态 `DRAFT → REVIEWED → PUBLISHED`
  - 未确认草稿禁止发布
  - 兼容代理 `/api/**`：迁移期间把未完成模块转发到现有 Node API

### 示例作业

- 名称：初一数学·有理数基础练习
- 题型：1 道单选题、1 道判断题、1 道一元一次方程单选题。
- 示例只用于演示，不包含学生姓名、学号等真实身份信息。

## 3. 强约束

- AI 不决定最终对错和最终得分。
- AI 不得把“可能原因”表述为已证实事实。
- AI 生成的草稿不得直接发布。
- 已发布讲评修改前必须进入撤回或新版本流程。
- 批改数据变化后，旧讲评需标记过期或重新生成。
- 删除业务数据优先改为停用或归档，保留历史追溯。
- 发送给 AI 的数据不得包含姓名、学号等身份信息。

## 3.1 与旧 Mark 系统的关键差异

| 旧系统能力 | 新版处理 |
| --- | --- |
| 文本、文件、图片、视频、代码等多种题型 | 第一版只保留单选题、判断题 |
| AI 可能参与自由评分 | Java 根据标准答案确定对错与得分 |
| AI 内容出口较多 | AI 只生成教学分析和讲评草稿 |
| AI 结果可能直接影响学生 | 必须经教师审核确认后发布 |
| 学生 AI 聊天、自动出题、文件识别 | 暂不进入第一版 |
| React/TypeScript 前端 | 新建 Vue 3 + JavaScript + HTML/CSS 前端 |
| NestJS 单体现状 | 新建 Java/Spring Boot 网关，未迁移模块暂时兼容代理 |

## 4. 实施前仍需确认的 P0 规则

以下规则来自需求文档，当前不能由代码擅自决定：

1. 登录、JWT/Session 与权限由谁提供。
2. 教师、学生、教研负责人的完整权限矩阵。
3. 教师—班级、学生—班级、学生转班与历史班级关系。
4. 一份作业是否布置给多个班级，统计是否按班级隔离。
5. 题目是否跨作业复用，知识点是否一题多个。
6. 知识点粒度与薄弱知识点阈值。
7. 单选题选项数量是否固定，是否存在多选题。
8. 判断题内部存储格式与前端显示格式。
9. 批改数据由逐题录入还是 Excel 导入。
10. Excel 重复导入、修改批改和修改原因规则。
11. 未作答是否计错，错误率分母采用全班人数还是实际作答人数。
12. 统计小数位数、四舍五入和重点错题筛选规则。
13. AI 第一版具体输出条目和结构。
14. AI 失败时固定模板、人工填写和部分成功发布规则。
15. 讲评条目状态与整份讲评状态。
16. 发布后撤回、修改、重新审核和版本关系。
17. 删除或修改批改数据后旧讲评如何失效。
18. 学生订正提交内容、重复订正和“完成”定义。
19. 典型班级人数、作业题量和并发规模。
20. DeepTutor 模型额度、费用承担和统一降级方案。

## 5. 推荐下一步

1. 老师确认本文第 4 节中的业务规则。

4. 把 Java 讲评内存存储替换为正式持久化。
5. 实现班级学生、作业发布、批改导入和订正 API。
6. 完成教师端和学生端全流程联调后再切换默认入口。
